# 1단계: 기획

글을 쓰지 않는다. 글의 **핵심을 붙잡아** 뒤 단계가 모두 같은 방향을 보게 한다.
결과물 `brief.md` 가 이후 모든 단계의 기준이다.

## 질문 순서

한 번에 2~4개씩 묻고 답을 받은 뒤 넘어간다. 작성자가 메모를 붙였으면 메모로 답이 되는 질문은 건너뛰고, 메모에서 읽은 것을 "이렇게 읽었다"로 확인만 받는다.

### 1. 핵심 의도
- 독자가 읽고 나서 가져가길 바라는 주장은 한 문장으로 무엇인가.
- 입장을 정한 글인가, 아직 고민 중인 것을 펼쳐 보이는 글인가.
- 이 글을 쓰게 된 계기는 무엇인가(답답함, 관찰, 알게 된 것).
- 은연중에라도 반대하는 생각은 무엇인가.

### 2. 독자와 자리
- 누가 읽는가. 그 독자가 이미 아는 것과 믿는 것은 무엇인가.
- 철학 / 기술 / 뉴스 중 어디인가. 시리즈의 한 편인가.
- 길이는 어느 정도인가. 참고로 지금 철학 글 세 편은 파일 기준 6천~9천 자다.
- 문체는 `CLAUDE.md` 「문체」 기준(합니다체)대로 가는지, 다른 이유가 있는지.

### 3. 갈래와 구조
- 메모에서 읽은 갈래를 나열하고 묻는다: "이런 갈래들이 보입니다: … 이 중 꼭 있어야 하는 것은 무엇인가."
- 갈래가 다섯 개를 넘으면 한 글에 다 들어가는지, 한 갈래를 다른 글로 뺄지 묻는다.
- 흐름은 문제 → 진단 → 처방인가, 다른 모양인가.
- 도입에서 세울 질문(인용 블록으로 쓸 한 문장)이 있는가.

### 4. 사례와 빈 곳
- 원칙마다 붙일 **실제 사례**를 받는다. 사례는 작성자가 겪은 일이나 확인한 사실만 쓴다(`CLAUDE.md` 「글쓰기 원칙」 지어낸 일화 금지). 받은 사례는 `brief.md` 에 작성자 말 그대로 적는다.
- 메모에서 뜻이 덜 잡힌 낱말·주장이 있으면 "X 는 무슨 뜻인가" 로 묻는다.
- 언급만 하고 넘어간 것이 중심인지 곁가지인지 묻는다.
- 버전·수치·API 동작처럼 확인이 필요한 사실을 표시한다.
- 절대 말하거나 암시하면 안 되는 것은 무엇인가(회사·사람이 특정되는 내용 등).

### 5. 형식과 맺음
- 소제목은 몇 단계까지 쓰는가. 대비할 두 대상이 있어 표가 필요한가.
- 끝은 요약 목록 뒤 짧은 문단인가(`CLAUDE.md` 「글의 구성」 맺음), 열린 질문인가.
- 제목과 `description` 후보가 있는가.

## 결과물: `brief.md`

`_workspace/flow-pair/<글 이름>/brief.md` 에 쓴다.

```markdown
# 기획: <가제>

## 핵심 의도
- 핵심 주장: (한 문장)
- 입장: 정한 입장 / 고민을 펼침 / 둘 다
- 계기:
- 반대하는 생각:

## 독자와 자리
- 독자: (누구, 무엇을 알고 믿는가)
- 분류: 철학 / 기술 / 뉴스, categories 후보, 시리즈 여부
- 길이: (본문 글자 수 목표)
- 문체: 합니다체(CLAUDE.md 「문체」) / 다른 경우 이유

## 구조
- 흐름: (문제 → 진단 → 처방 등)
- 꼭 있어야 하는 갈래:
- 뺄 수 있는 갈래:
- 도입 질문: > "..."

## 사례 (작성자가 준 것만)
- (원칙) ← (사례, 작성자 말 그대로)
- 사례가 아직 없는 원칙:

## 제약
- 꼭 넣을 것:
- 넣지 않을 것:
- 확인할 사실:
- 맺음:

## 형식
- 소제목 단계, 표 위치, 굵게 쓸 핵심 문장 후보

## 원자료
(작성자의 메모를 그대로 붙이거나 요약)
```

## 규칙

- 작성자가 서둘러도 1~4번 질문은 건너뛰지 않는다. 특히 4번 사례가 비면 초안에서 빈칸이 늘어난다.
- "넣지 않을 것"은 "넣을 것"만큼 중요하다. 분명히 적는다.
- 원자료를 남긴다. 뒤 단계가 원래 말을 다시 볼 일이 생긴다.
