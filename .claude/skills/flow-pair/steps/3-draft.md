# 3단계: 초안

기획서가 *무엇을*, 개요가 *어떤 순서로*를 정했다. 이 단계는 *어떻게*, 곧 문장과 리듬을 찾는다.

## 준비

- `brief.md`(필수에 가깝다), `outline.md`(권장)를 읽는다. 기획서가 없으면 메모로 쓰되 정확도가 떨어진다고 말한다.
- `CLAUDE.md` 의 「문체」 절이 고른 기준 글 중 같은 종류(철학 / 기술) 한 편을 읽고 귀를 맞춘다.
- 「글 작성 기준 (`_posts/`)」 절을 보고 위치·파일명·frontmatter 를 정한다.

## 쓰기 전에 확인

> 이렇게 쓰려고 합니다.
> - 주장:
> - 흐름:
> - 문체:
> - 길이:
> - 도입 질문:
> - 맺음:
> - 파일: `_posts/<폴더>/<파일명>.md`
>
> 이대로 쓸까요.

## 쓰기

- 한국어판만 쓴다. 영어판은 7단계 게시에서 만든다.
- 파일은 `_posts/` 의 제자리에 바로 만든다. `tools/blog_mcp.js` 는 쓰지 않는다(바로 커밋·push 해서 영어판 없는 초안이 main 에 올라간다).
- 개요의 구간을 차례로 따른다. 구간마다 개요의 목적을 해내고, 길이를 대략 맞추고, 개요에 적은 긴장을 남기며 끝낸다.
- 문체·구성은 `CLAUDE.md` 「문체」·「글의 구성」을 따른다.
- 원칙만 늘어놓지 않는다. 추상적인 말 뒤에는 기획서의 구체 사례를 붙인다.
- "이 글에서는 …를 다룬다" 같은 안내문, 비유를 설명하는 문장, 긴장을 너무 깔끔하게 풀어 버리는 맺음을 피한다.

## 빈칸과 의문 표시

확신이 없는 곳에는 본문에 표시를 남긴다. 고치기 단계가 이 표시부터 본다.

- `[?? 사례 필요: 무엇을 물을지]`: 사례가 없는 자리. **사례를 지어내지 않는다.**
- `[?? 확인 필요: 무슨 사실]`: 버전·수치·동작을 확인하지 못한 곳.
- `[?? 이 구간이 길다]`, `[?? 문체가 흔들림]`: 쓰다가 걸린 곳.

표시는 7단계 게시 전에 모두 없어져야 한다. `check_posts.py` 는 이 표시를 잡지 못하므로 게시 단계에서 따로 찾는다.

## 결과 보고

초안을 쓴 뒤 작성자에게 다음을 보고한다(파일에는 넣지 않는다).

```
## 초안 메모
- 잘 붙은 곳:
- 남긴 표시: (위치와 이유)
- 길이: 목표 N자 / 실제 M자
- 개요와 달라진 곳: (있으면 이유)
```

## 규칙

- 기획서의 "넣지 않을 것"을 넣지 않는다.
- 초안을 지나치게 다듬지 않는다. 이 단계는 끝까지 가는 것이 먼저다.
- 개요에서 벗어나면 밝히고 이유를 적는다.

## 넘기기

> 초안을 `_posts/...` 에 썼습니다. 다음은 **고치기**(표시한 곳부터 한 곳씩) 또는 **검토**(전체 진단)입니다. 먼저 직접 읽고 메모를 주셔도 됩니다.
