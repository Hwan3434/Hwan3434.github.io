# 7단계: 게시

한국어판을 작성자가 "됐다"고 확정한 뒤에 한다.

## 1. 남은 표시 찾기

```bash
grep -n '\[??' _posts/<폴더>/<파일명>.md
```

결과가 있으면 게시하지 않는다. 표시마다 작성자에게 묻거나 4단계로 돌아간다.

## 2. 영어판

`CLAUDE.md` 「글 작성 기준 (`_posts/`)」의 영어판 규칙대로 만든다.

- 위치는 같은 종류의 영어판 폴더(`_posts/en/tech/`, `_posts/en/philosophy/`, `_posts/en/news/`), 파일명은 한국어판과 **같게** 한다.
- `title`·`description`·`tags`, `categories` 세부, `series` 제목을 옮긴다. 대분류와 `date` 는 그대로 둔다.
- 본문은 한국어판과 같은 순서·같은 주장·같은 소제목 구조로 옮긴다. 새 문장이나 예시를 더하지 않는다.
- 이미 영어판이 있으면 한국어판에서 바뀐 곳만 맞춘다.

## 3. 형식 검사

```bash
python3 tools/check_posts.py
```

위반 0건이어야 한다. 위반이 나오면 `파일: 무엇을 어겼는지` 를 보고 고친다.

## 4. PR

전역 규칙(브랜치 이름, 바꾼 파일만 골라 담기, `#숫자` 쓰지 않기)대로 커밋하고 PR 을 연다.

PR 본문에 남길 것:

- 글 주소(배포 후 생길 `/posts/...` 와 `/en/posts/...`)
- `brief.md` 요지: 핵심 주장, 독자, 꼭 넣을 것·넣지 않을 것, 사례 출처
- `outline.md` 의 관통선과 구간 목록
- 마지막 `review.md` 전문
- 6단계 솔직한 평가의 「한마디」

`_workspace/` 는 커밋되지 않고 워크트리를 지우면 사라진다. 기획 기록은 이 PR 본문이 맡는다.

## 5. 병합과 확인

- 병합은 작성자에게 묻고 한다(`gh pr merge <번호> --squash`).
- 병합 뒤 `pages-deploy.yml` 배포가 끝나면 배포된 한국어판·영어판 페이지에서 바뀐 문단과 한영 전환 버튼을 확인한다.
- 작은 수정을 곳마다 바로 내보내 달라고 하면 1~5를 곳마다 돈다.
