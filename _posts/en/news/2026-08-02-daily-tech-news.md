## Today's Developer News: Astra's Lean-Certified Results, Google Agent Evals GA, a Lean Kernel Bug Postmortem, and NetBSD 11.0

Here is a developer-focused digest for August 2, 2026, covering ten mathematics and theoretical-computer-science results from OpenAI, generally available agent and model evaluations in Gemini Enterprise Agent Platform, the postmortem for a Lean kernel soundness bug found with AI assistance, and NetBSD 11.0's expanded RISC-V and microVM support. ### AI for Formal Research

*   **OpenAI publishes ten Astra-generated mathematics and theoretical-CS results with Lean certificates**
    OpenAI has released new results for ten problems that it says had seen no progress on their main result for at least a decade, spanning high-dimensional sphere packing, code bounds, non-sofic groups, arithmetic circuit complexity, quantum parallel repetition, and the lattice closest-vector problem. The mathematical arguments were generated by an internal version of Astra, its next major model; humans then prepared manuscripts with the same model, which formalized every argument as a Lean certificate. OpenAI estimates that the discovery tokens would cost roughly $2,000 at Sol API rates, but Astra is not itself a public API and the figure converts these particular runs rather than reporting a reproducible public benchmark. Lean certificates make formal consistency checkable by a type checker, while the results' significance, relationship to prior literature, and whether each formal statement precisely captures the intended theorem still require domain-expert review. For teams evaluating research agents, the notable pattern is publishing machine-checkable artifacts alongside the human editing boundary and model-compute cost, rather than reporting final answers alone.
    [Source URL](https://openai.com/index/ten-advances-in-mathematics/) (OpenAI)

### Agent Evaluation

*   **Google makes Agent Platform evaluations GA with shared metrics across experiments and production traffic**
    Agent and model evaluations in Gemini Enterprise Agent Platform provide more than 20 built-in metrics for quality, safety, grounding, tool use, and trajectory, plus custom code and LLM-as-a-judge metrics. During development, teams can run local or server-side experiments and use a case generator, a multi-turn user simulator, and an environment simulator that substitutes failed or delayed tool responses. After deployment, the same metrics can sample Cloud Trace sessions and traces for continuous evaluation and drift alerts. Server-side artifacts remain in Cloud Storage for versioning and audit, while issue clustering groups failures against a team's taxonomy. Local evaluation can use models from any provider, and server-side runs support Gemini and Anthropic models in Model Garden. Model-based metrics incur their underlying model-call and artifact-storage costs, however, and an LLM judge can itself be wrong, so deterministic checks and a human-reviewed calibration set should remain part of the evaluation stack.
    [Source URL](https://developers.googleblog.com/agent-and-model-evaluations-in-gemini-enterprise-agent-platform-are-now-ga/) (Google Developers Blog)

### Formal Verification Security

*   **Lean fixed the kernel soundness bug behind an AI-assisted Collatz “disproof” one hour after its report**
    A `sorry`-free disproof of the Collatz conjecture published on July 25 was not a valid proof: it exploited a Lean kernel bug in which phantom parameters of a nested inductive type disappeared from a generated auxiliary type and escaped type checking. The ordinary frontend rejects the malformed argument, so the path requires metaprogramming that sends a declaration directly to the kernel, but the elaborator is intentionally outside the trusted boundary and the kernel must reject such input itself. A minimized proof of `False` was reported as issue `#14576` on July 28; a fix followed within an hour, with patch releases and regression tests now available. The independent Rust checker nanoda also accepted the original proof because of a separate projection type-name validation bug, although that flaw had already been fixed a week before the Lean report. Follow-up work strengthened parameter checks, repaired additional programming mistakes found with an AI cybersecurity system, and made `comparator.live` run a current nanoda by default. Independent checking still provides value, but users must keep both implementations current and account for checkers that port the same reference code and may inherit its defects.
    [Source URL](https://leodemoura.github.io/blog/2026-8-1-postmortem-for-kernel-soundness-bug-14576/) (Leonardo de Moura / Lean FRO)

### Operating Systems

*   **NetBSD 11.0 adds stable 64-bit RISC-V support and an x86 MICROVM kernel designed to boot in about 10 ms**
    NetBSD 11.0 is the project's first stable release with 64-bit RISC-V support, covering the VisionFive 2, PINE64 STAR64, and QEMU, and it adds initial Qualcomm Snapdragon X Elite support. A new x86 `MICROVM` kernel uses PVH boot, VirtIO MMIO, and kernel optimizations to target roughly 10 ms boots on 2020-era CPUs. The Linux compatibility layer gains `epoll`, `statx`, `close_range`, `clone3`, and `inotify`, while POSIX.1-2024 and C23 compliance and NPF layer-2 and user/group filtering expand. Upgraders should install the kernel and modules first, reboot, and then update userspace and third-party packages, while reviewing incompatible changes including removal of OpenSSH DSA keys and `ctype(3)` guard pages that turn previously incorrect use into a segfault. The project also disclosed three unresolved pullups at release: a missing hdaudio privilege check, an IPFilter null dereference, and a use-after-free in deprecated PF. It plans to land them on the stable branch and is targeting 11.1 within roughly two months, so Internet-facing deployments should track the workarounds and actual 11.1 inclusion rather than relying only on whether each feature is enabled by default.
    [Source URL](https://blog.netbsd.org/tnf/entry/netbsd_11_0_released) (NetBSD Project)
