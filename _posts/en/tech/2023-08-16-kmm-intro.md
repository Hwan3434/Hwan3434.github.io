> Originally posted on velog in 2023 and moved here.

Somehow KMM ended up being the first topic of this blog.

As a developer who loves native, I find KMM a really attractive technology.
There have been plenty of multiplatform tools, like Xamarin, RN and Flutter,
but I could never shake the thought: "UI should be native!"

That's fine, though.
With KMM I can finally build the structure I always wanted!

## Before We Start

With KMM, the UI is built natively and the business logic lives in KMM.
Which raises a question:
why doesn't KMM handle the UI too?

Business logic is very abstract.
As long as you have the concept, you can implement it on any platform.
UI is different. Each platform runs its own graphics engine,
and the way UI is drawn can differ from engine to engine.
The views each platform uses aren't abstractions; they're already implemented, so supporting all of them one by one costs far too much.
(Xamarin, RN and Flutter, which I mentioned above, each do this in their own way.)

## KMM

> KMM stands for Kotlin Multiplatform Mobile, a framework made by JetBrains.
> Think of it as a module written in Kotlin and shared by Android and iOS.
> It takes care of the business logic closely tied to the domain you're building.
> (Fetching data, special calculations, any code that belongs in business logic: it's up to how you build it.)

![KMM structure](/assets/img/posts/kmm/intro-01.png)

The image above comes from JetBrains' official KMM page.
So it can share common logic not only with mobile but with the server as well. 🎉 (Wouldn't that get too big, though?)

In practice, servers won't use KMM. (The name itself is Kotlin Multiplatform *Mobile*!)
Unlike clients, servers care a great deal about processing speed.
Most client logic is written for readability and maintainability rather than speed, so I don't see a reason to use it on the server.
(Enums, models and CONST values in common might still be shareable.)

## So Here's the Thing!

1. **iOS has no JVM. How does it compile Kotlin?**
   A Kotlin compilation module is added to the actual iOS app.
   The iOS build then uses the binary produced by the Kotlin compiler.
2. **If the Android app is written in Java, how is KMM built?**
   Same as iOS. The compiler that builds the app and the compiler that builds the KMM module are different.
   The app is built through Dalvik or ART as configured in Gradle, while the KMM module uses the Kotlin native compiler.

### Conclusion

Builds that use KMM can be slower than pure native builds.
