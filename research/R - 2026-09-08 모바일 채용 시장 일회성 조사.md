### 조사 개요

기존 [[주간 모바일 채용 다이제스트]] 파이프라인(`tools/job_scraper.py`)이 [[원티드]] 단일 소스에 의존해 7월 말부터 수집이 사실상 멈춘 상태를 확인한 뒤, 원티드 외 채널을 수동으로 조사한 일회성 스냅샷이다.

-   **조사일:** 2026-09-08
-   **범위:** 국내 테크 기업 자체 채용 페이지 + 채용 플랫폼(원티드 / 점핏 / 랠릿 / 사람인 / 잡코리아)
-   **방법:** 웹 검색 기반. 실행 환경의 egress 프록시가 `boards-api.greenhouse.io`, `api.lever.co`, `wanted.co.kr`, `careers.kakao.com` 등을 차단해 [[ATS]] API 직접 호출은 불가능했다.

> [!warning] 신뢰도 한계
> 검색 결과는 **공고 게시일·마감 여부를 보장하지 않는다.** 특히 원티드 URL 중 ID가 낮은 건(`/wd/483`, `/wd/11767` 등)은 수년 전 공고가 색인에 남아 있는 경우다. 아래 목록은 "이 회사가 이 직군을 채용하는 채널"의 지도이지, 오늘 열려 있는 공고의 확정 목록이 아니다.

### 발견 2 — Flutter는 다른 시장에 있다

위 표의 대기업·유니콘 목록에서 **Flutter 포지션은 한 건도 확인되지 않았다.** Flutter 수요는 다른 층위에 형성되어 있다.

-   **스타트업 / 에이전시:** 더블디, 문토, 다이노즈, 럽맘, 클레온, 왓콘, 피트 등 (랠릿 · 점핏 중심)
-   **경력 스펙트럼이 넓다:** 신입 공고와 7~10년 시니어 공고(클레온)가 동시에 존재
-   **금융권 진입 사례:** 교보증권 DigitalFrontierLabs가 Flutter + Firebase + Go 스택으로 채용 — 대형 조직의 [[Flutter]] 도입이 사내 플랫폼·신규 프로덕트부터 시작되는 전형적 패턴
-   **플랫폼별 물량:** 잡코리아 기준 "플러터" 173건 / "flutter" 106건

즉 국내 시장은 **트래픽 규모가 큰 기존 서비스는 네이티브 유지, 신규·내부 프로덕트는 Flutter**로 갈리는 이원화 구조다. 글로벌 통계상 크로스플랫폼 점유율(Flutter 약 40%, React Native 약 38%)과 국내 대형 서비스의 채용 수요는 상당히 어긋나 있다.

### 발견 3 — 스크래퍼 확장에 바로 쓸 수 있는 단서

조사 중 확인된 **ATS 식별 정보**가 기존 파이프라인 개선의 핵심 자산이다.

당근(`4496730003`, `5282170003`)과 토스(`7131429003`)의 job_id는 [[Greenhouse]] 고유 ID 포맷(10자리, `003` 접미)이다. 두나무는 `job-boards.greenhouse.io/dunamu`로 직접 확인됐다. 즉 이 회사들은 공개 [[Greenhouse Job Board API]]로 수집 가능하다.

```python
# 기존 scrape_coupang() 을 board token 목록으로 일반화하면
# 회사별 함수를 새로 짤 필요가 없다
GREENHOUSE_BOARDS = {
    'coupang':     '쿠팡',
    'dunamu':      '두나무',
    'bucketplace': '오늘의집',
    # 당근 / 토스는 board token 확인 필요
}

def scrape_greenhouse(token: str, company: str) -> list[dict]:
    url = f"https://boards-api.greenhouse.io/v1/boards/{token}/jobs"
    ...
```

또 하나의 축은 **[[그리팅]](greetinghr)** 이다. 무신사 · 카카오페이 · 카카오모빌리티가 모두 `*.career.greetinghr.com` 서브도메인을 쓴다. 국내 스타트업 표준 ATS이므로 여기 대응 파서를 하나 만들면 커버리지가 크게 늘어난다.

### 다음 액션 후보

1.  **소스 다변화:** Greenhouse board token 목록 + 그리팅 파서 추가. 원티드 단일 의존 해소
2.  **조용한 실패 제거:** `scrape_*()` 의 `except: pass` 를 걷어내고 수집 0건이면 워크플로를 실패시킬 것
3.  **Flutter 전용 트랙 분리:** 네이티브와 Flutter는 시장이 다르므로 소스도 달라야 한다. 점핏 · 랠릿을 Flutter 전용 소스로 추가
4.  **게시일 확보:** 현재 `created_at` 은 "우리가 처음 본 시각"이지 공고 게시일이 아니다. ATS API는 `updated_at` 을 제공하므로 이를 저장하면 신선도 판정이 정확해진다
